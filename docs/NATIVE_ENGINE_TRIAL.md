# Native engine decision trial — free-only (2026-11-26)

The owner authorizes installing any suitable free engine and changing the architecture. This is a plan, not an implemented migration or benchmark. Browser compatibility is optional; prioritize Windows desktop, GTX 1650-class GPU, 16 GB RAM, 1080p, scalable graphics. Preserve legacy reference and same repository.

## Candidate approach
- Godot 4 stable: MIT open-source; free commercial development without engine royalties. Use Forward+ and compare Compatibility if needed. Official download https://godotengine.org/download/windows/ and license https://godotengine.org/license/ . Prefer for guaranteed zero engine fee.
- Unity: evaluate current Unity Personal eligibility and terms before selecting, use URP for the hardware; official https://unity.com/download and https://unity.com/products/unity-personal . Do not activate paid plan. Use free Starter Assets only after checking asset terms.
- Unreal Engine: evaluate current game royalty/eligibility and system requirements at https://www.unrealengine.com/en-US/download and https://www.unrealengine.com/en-US/license . Do not treat a conditional royalty model as unconditional free. If free-only means no possible future fees, choose Godot.
- Existing Three.js baseline: preserve as migration reference, not as mandatory final engine.

Use Blender (https://www.blender.org/download/), Poly Haven (https://polyhaven.com/), ambientCG (https://ambientcg.com/), licensed free character/animation packs and recorded audio. Verify asset-specific commercial-use and redistribution rights, not merely zero download price. Avoid using the current primitive models as final assets. Use Blender to retarget/customize/optimize professionally designed models.

## Trial specification
Create a native project subdirectory within this repository (e.g. native/), not another repo; ignore generated engine caches and binaries. Preserve source until validated. Install selected engine via official installer, record exact version, GPU driver and render backend. Build a 50–100 m forest section with actual terrain, realistic hero model, one shield/sword, one enemy, real locomotion and attack clips, footstep/impact audio and minimal HUD. Make the same route available for comparison. Use physically-based assets, appropriate contact shadows and sky, capsule character controller, collision layers and navigation meshes. Avoid placeholder screenshots as finished product.
Measure 1080p low/medium/high on local GPU; warm up, run an identical 60-second traversal/combat route three times without screen recording; log average FPS, 1% low or p95 frame time, GPU/CPU/RAM/VRAM use; run separately with audio capture. Target 60 FPS if feasible, explicitly note if not met. Compare real movement response, foot sliding, camera collision, attack anticipation/active/recovery, parry, stagger, visual quality and authoring time. Select based on results, not promises. Document ENGINE_DECISION.md and actual build logs.

## Migration contracts
Port stable IDs and data from src/content/eidrathContent.ts, src/game/types.ts, src/game/rpg/rpgLogic.ts and src/game/save/saveSystem.ts. Preserve quest conditions, reward idempotency, inventory stack semantics, two-handed equip rules, factions, companion morality, boss phases, skills and difficulty. Create a versioned JSON save importer/exporter using existing v1 fields; never delete web data. Preserve dialogue and quest state. Separate content data from runtime systems and write engine-side unit/integration tests. Use native animation state machine, root-motion or speed-matched in-place clips, authored hit markers, swept collision, physics capsule, camera obstruction radius and navmesh AI. Integrate real 3D spatial audio. Ship a Windows executable with a reproducible free build path, not just a scene screenshot.
